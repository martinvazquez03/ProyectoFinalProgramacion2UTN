Armé la estructura de carpetas para el proyecto:
src/config, src/dao, src/dao/impl, src/model, src/enums, src/interfaces, src/exception, src/service, src/service/impl, src/util, src/controller, src/view.

1- enums : RolUsuario, EstadoVehiculo, EstadoReserva y EstadoOcupacion. Así ya tenía las constantes que iba a usar después.

2- interfaces. Alquilable para marcar que un vehiculo puede alquilarse y Auditable para llevar registro de fecha/usuario.

Después fui con el modelo. Cree Persona como clase abstracta, con atributos privados, getters/setters, método abstracto getIdentificacion() y getNombreCompleto(). De ahi heredaron Cliente y Empleado. También hice Vehiculo como clase abstracta implementando Alquilable, y de ahi hereda Automovil.

Seguí con Usuario, Reserva, Ocupacion, Entrega, Devolucion. Todos aplicando encapsulamiento. En Reserva y Ocupacion implemente Auditable.

Para cumplir con genéricos, cree DAOGenerico<T> y RepositorioGenerico<T, ID> con método genérico mapear(Function<T,R>). También use ArrayList y HashMap como colecciones.

Para la persistencia arme ConnectionFactory con JDBC y SQLite. Cree UsuarioDAO y VehiculoDAO implementando DAOGenerico. Inicialicé las tablas usuario y vehiculo con CREATE TABLE IF NOT EXISTS.

Luego arme el sistema con una capa envolvente: SistemaAlquiler. Ahí metí toda la lógica para mantener el encapsulamiento. El Main solo quedó para el menu con switch, pedir datos e imprimir lo que me devuelve SistemaAlquiler.

Hice que el login lea directamente de la BD. También hice que listarDisponibles(), listarNoDisponibles(), verFlotaPolimorfismo(), administrarUsuarios() lean desde SQLite mediante los DAOs.

Agregué la opción 1 para crear usuarios. Primero solo para admin, luego modifiqué para que empleado también pueda crear usuarios, pero solo un admin puede crear otro admin. Ahora se elige el rol desde un submenú.

Agregué la opción 6 para agregar vehículos a la BD. Solo puede hacerlo un admin o un empleado. Valido que no exista la patente.

Reorganicé el menú para que crear usuario quede primero y corrí las opciones.

Modifiqué las opciones de listado para que lean directamente desde la BD, carguen los datos a un ArrayList genérico y recien ahí se muestren desde el Main.

Agregué validaciones al crear un automóvil: la marca no puede estar vacía ni contener números, el año no puede superar el año actual ni ser menor a 1900, kilometraje y precios válidos.

Arreglé la opción 4 para mostrar automóviles alquilados leyendo desde BD por estado ALQUILADO.

La opción 7 ahora permite crear clientes desde ahí. Si no hay clientes, es obligatorio crearlos.

Para las entregas/devoluciones, permití que tanto Administrador como Empleado las realicen.

Cambié el rol CONDUCTOR por CLIENTE en todo el proyecto para evitar conflictos.

Agregué la opción 14 para limpiar toda la BD excepto el usuario mariano, con lógica en GestorBaseDatos.

GestorBaseDatos para inicializar tablas, guardar clientes, reservas, ocupaciones, entregas, devoluciones y para limpiar datos.

Por último, hice que al inicializar el programa se carguen desde la BD todos los datos (clientes, vehículos, empleados y reservas) a sus respectivos contenedores genéricos (ArrayList y RepositorioGenerico).
