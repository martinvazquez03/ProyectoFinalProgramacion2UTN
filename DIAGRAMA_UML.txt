DIAGRAMA UML - SISTEMA DE ALQUILER DE VEHICULOS
================================================

1. PAQUETES
-----------
[model]        -> Persona, Cliente, Empleado, Usuario, Vehiculo, Automovil, Reserva, Ocupacion, Entrega, Devolucion
[enums]        -> RolUsuario, EstadoVehiculo, EstadoReserva, EstadoOcupacion
[interfaces]   -> Alquilable, Auditable
[exception]    -> VehiculoNoDisponibleException, ReservaInvalidaException, UsuarioNoAutorizadoException, BaseDatosException
[dao]          -> GestorBaseDatos
[config]       -> ConnectionFactory
[service]      -> SistemaAlquiler, ServicioAlquiler
[service.impl] -> ServicioAlquilerImpl
[util]         -> RepositorioGenerico<T, ID>
[Main]         -> Clase principal con menu

2. HERENCIA
-----------
                <<abstract>>                <<abstract>>
                   Persona                    Vehiculo
                  /       \                      \
               Cliente   Empleado              Automovil
                (concreta)(concreta)            (concreta)

Persona  -> Atributos: id, nombre, apellido, dni, telefono, email
           Metodos: getNombreCompleto(), getIdentificacion() [abstracto]

Vehiculo -> Atributos: patente, marca, modelo, anio, kilometraje, estado, precioDia, tarifaSeguro
           Metodos: calcularCosto(int) [abstracto], estaDisponible(), requiereSeguro()

3. IMPLEMENTACION DE INTERFACES
-------------------------------
Vehiculo             -->|implements|--> Alquilable
Reserva              -->|implements|--> Auditable
Ocupacion            -->|implements|--> Auditable
ServicioAlquilerImpl -->|implements|--> ServicioAlquiler

4. ENUMERACIONES
----------------
RolUsuario        = { ADMINISTRADOR, EMPLEADO, CLIENTE }
EstadoVehiculo    = { DISPONIBLE, ALQUILADO, RESERVADO, EN_LIMPIEZA, EN_REPARACION, FUERA_SERVICIO }
EstadoReserva     = { PENDIENTE, CONFIRMADA, CANCELADA, CONCRETADA }
EstadoOcupacion   = { ACTIVA, FINALIZADA, CANCELADA }

Nota: los tres roles inician sesion. CLIENTE solo puede ver automoviles disponibles y crear
reservas; sus reservas heredan automaticamente su ficha de Cliente (no elige cliente).
Sin sesion iniciada, la opcion 8 solo permite autorregistrarse como CLIENTE.

11. PERSISTENCIA - BASE DE DATOS
-------------------------------
Motor: SQLite (alquiler_vehiculos.db)
Tablas: usuario, vehiculo, cliente, empleado, reserva, ocupacion, entrega, devolucion
GestorBaseDatos maneja todo el SQL. SistemaAlquiler delega operaciones BD a GestorBaseDatos.
Migraciones: agregarColumnaSiFalta para reserva.creado_por, ocupacion.id_reserva,
ocupacion.creado_por, ocupacion.fecha_reserva y ocupacion.fecha_inicio_reserva.
Tambien se elimina la columna legacy reserva.monto_senia si existe.
Al entregar se borra la reserva de la tabla reserva y del contenedor; la ocupacion
conserva fecha_reserva/fecha_inicio_reserva y fechaFinReserva se deriva de fechaFinEstimada.

12. FLUJO FUNCIONAL
-------------------
1. Main crea SistemaAlquiler (inicializa BD, migra columnas, crea mariano/1234 con Empleado, carga datos)
2. Usuario inicia sesion (ADMIN/EMPLEADO o CLIENTE; consulta BD y adjunta su Empleado o Cliente)
3. Usuarios: sin sesion solo se autorregistra CLIENTE; con sesion ADMIN/EMPLEADO crean Empleado+Usuario o Cliente+Usuario; solo ADMIN crea ADMIN
4. ADMIN/EMPLEADO agregan automoviles con validaciones y datos reales de puertas/transmision
5. Listados leen desde BD, cargan contenedores genericos y se muestran
6. Clientes se crean con el constructor de Cliente (Persona)
7. Reservas/Entregas/Devoluciones se persisten con el usuario/empleado real; la reserva de un CLIENTE usa su ficha
7b. Opcion 12: submenu crear/cancelar. Cancelar pasa la reserva a CANCELADA y persiste; CLIENTE solo cancela las propias, ADMIN/EMPLEADO cualquiera
7c. La entrega guarda la instantanea de fechas de la reserva en la ocupacion y elimina la reserva de la BD y del contenedor
8. Opcion 15 elimina clientes/vehiculos/reservas/usuarios (bloquea ocupaciones activas y borra en cascada las finalizadas)
9. Opcion 16 limpia BD manteniendo solo mariano (y restaura su legajo)
10. Polimorfismo con ArrayList<Vehiculo>, genericos con RepositorioGenerico
