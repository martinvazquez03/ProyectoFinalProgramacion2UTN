DIAGRAMA UML - SISTEMA DE ALQUILER DE VEHICULOS
================================================

1. PAQUETES
-----------
[model]        -> Persona, Cliente, Empleado, Usuario, Vehiculo, Automovil, Reserva, Ocupacion, Entrega, Devolucion
[enums]        -> RolUsuario, EstadoVehiculo, EstadoReserva, EstadoOcupacion
[interfaces]   -> Alquilable, Auditable
[exception]    -> VehiculoNoDisponibleException, ReservaInvalidaException, UsuarioNoAutorizadoException, DatoInvalidoException, BaseDatosException
[dao]          -> GestorBaseDatos
[config]       -> ConnectionFactory
[service]      -> SistemaAlquiler, ServicioAlquiler
[service.impl] -> ServicioAlquilerImpl
[util]         -> RepositorioGenerico<T, ID>
[Main]         -> Bucle y switch principal; [MenuConsola] -> menus, submenus y consola

2. HERENCIA
-----------
                <<abstract>>                <<abstract>>
                   Persona                    Vehiculo
                  /       \                      \
               Cliente   Empleado              Automovil
                (concreta)(concreta)            (concreta)

Persona  -> Atributos: id, nombre, apellido, dni, telefono, email
           Metodos: getNombreCompleto(), getIdentificacion() [abstracto]

Vehiculo -> Atributos: patente, marca, modelo, anio, kilometraje, estado, precioDia, tarifaSeguro, activo
           Metodos: calcularCosto(int) [abstracto], estaDisponible(), requiereSeguro()

3. IMPLEMENTACION DE INTERFACES
-------------------------------
Vehiculo             -->|implements|--> Alquilable
Reserva              -->|implements|--> Auditable
Ocupacion            -->|implements|--> Auditable
ServicioAlquilerImpl -->|implements|--> ServicioAlquiler

4. ENUMERACIONES
----------------
RolUsuario        = { ADMINISTRADOR, EMPLEADO, CLIENTE }
EstadoVehiculo    = { DISPONIBLE, ALQUILADO, EN_LIMPIEZA, EN_REPARACION, FUERA_SERVICIO }
EstadoReserva     = { PENDIENTE, CONFIRMADA, CANCELADA, CONCRETADA }
EstadoOcupacion   = { ACTIVA, FINALIZADA, CANCELADA }

Nota: los tres roles inician sesion. CLIENTE solo puede ver automoviles disponibles y gestionar
sus propias reservas; sus reservas heredan automaticamente su ficha de Cliente (no elige cliente).
Sin sesion iniciada, el menu solo muestra iniciar sesion, crear usuario CLIENTE y salir. Con sesion,
MenuConsola muestra unicamente las opciones permitidas por el rol.

11. PERSISTENCIA - BASE DE DATOS
-------------------------------
Motor: SQLite (alquiler_vehiculos.db)
Tablas: usuario, vehiculo, cliente, empleado, reserva, ocupacion, entrega, devolucion
GestorBaseDatos maneja todo el SQL. SistemaAlquiler carga la BD en repositorios genericos y lee desde ellos;
las altas y modificaciones se aplican primero al repositorio y luego se persisten con GestorBaseDatos.
Migraciones: agregarColumnaSiFalta para reserva.creado_por, ocupacion.id_reserva,
ocupacion.creado_por, ocupacion.fecha_reserva, ocupacion.fecha_inicio_reserva, devolucion.observaciones,
cliente.activo, vehiculo.activo y usuario.activo.
Tambien se elimina la columna legacy reserva.monto_senia si existe.
Al entregar se borra la reserva de la tabla reserva y de repoReservas; la ocupacion
conserva fecha_reserva/fecha_inicio_reserva y fechaFinReserva se deriva de fechaFinEstimada.
reserva.creado_por y ocupacion.creado_por guardan usernames; la migracion inicial
convierte ids de usuario o legajos legacy al username correspondiente.

12. FLUJO FUNCIONAL
-------------------
1. Main crea SistemaAlquiler y MenuConsola (inicializa BD, migra columnas, crea mariano/1234 con Empleado, carga datos en repositorios); MenuConsola imprime y lee por teclado
   Menu: sin sesion solo iniciar sesion, crear usuario CLIENTE y salir. Con sesion agrupa en Clientes,
   Automoviles, Reservas, Entregas, Devoluciones y Usuarios; cada categoria tiene su subswitch y solo se muestran las permitidas por rol
2. Usuario inicia sesion (ADMIN/EMPLEADO o CLIENTE; consulta repoUsuarios y adjunta su Empleado o Cliente desde repositorios)
3. Usuarios: sin sesion solo se autorregistra CLIENTE; con sesion ADMIN/EMPLEADO crean Empleado+Usuario o Cliente+Usuario; solo ADMIN crea ADMIN. Clientes > Crear cliente tambien crea Usuario CLIENTE con username nombre_apellido y password DNI
4. ADMIN/EMPLEADO agregan automoviles con validaciones y datos reales de puertas/transmision
5. Listados leen desde repositorios genericos y conservan el orden de carga/alta
6. Clientes se crean con el constructor de Cliente (Persona)
7. Reservas/Entregas/Devoluciones se persisten con el usuario/empleado real; la reserva de un CLIENTE usa su ficha
7b. En Reservas, el submenu permite crear/cancelar y listar (ADMIN/EMPLEADO). Cancelar pasa la reserva a CANCELADA y persiste; CLIENTE solo cancela las propias, ADMIN/EMPLEADO cualquiera
7c. La entrega lista solo reservas PENDIENTES, usa reserva.fechaInicio como fecha de entrega e inicio de la ocupacion; guarda la instantanea de fechas y elimina la reserva de la BD y de repoReservas
7d. El historial muestra RESERVA, ENTREGA, DEVOLUCION y OBSERVACIONES cargadas al devolver el vehiculo; la entrega ya no pide observaciones
7e. La devolucion toma los cargos extra de Vehiculo.tarifaSeguro, sin pedirlos por teclado; la multa por daños se sigue aplicando automaticamente
8. En Clientes/Automoviles y Usuarios, solo ADMIN puede pasar registros de activo a inactivo; se bloquea si hay ocupacion activa y los datos se conservan en la BD pero dejan de listarse. Las reservas se cancelan con su estado
10. Polimorfismo con ArrayList<Vehiculo>, genericos con RepositorioGenerico para todas las entidades
